CHANGES SINCE PRE10

- Desktop node launchers now keep both public P2P nodes as priority peers.
- Local desktop daemons disable RPC-triggered peer banning so repeated GUI
  polling cannot ban loopback and strand the embedded wallet.
- The GUI embedded-daemon path uses the same dual-node and RPC-ban settings.
- Consensus identity, ports, address prefixes, supply rules, and the public
  asset hard-fork schedule are unchanged from Genesis pre10.

UPGRADE

Pre11 uses the same chain as pre10. Stop the wallet, miner, and daemon cleanly,
verify the new archive checksum, and extract it into a new directory. Existing
pre10 blockchain and wallet data do not require migration. Keep the previous
verified binaries until the updated client has synchronized and remained
healthy. Never reuse a Monero or other CryptoNote seed with Monzero.

TEST STATUS AND LIMITATIONS

The focused Linux and Windows CLI targets and native/Windows GUI targets built
successfully. Linux daemon RPC responsiveness and synchronization were checked
after launching with the new settings. The Linux, Windows CLI, and core source
archives passed their release verifiers; the Windows GUI ZIP passed compressed-
data, PE subsystem/import, embedded-version, and internal-manifest checks.
Pre10's broader source-suite results are not attributed to the new binaries.
The Linux package requires GLIBC 2.42 or newer. Native Windows execution,
independent reproduction, code signing, sustained fuzzing, and an external
audit remain outstanding. Windows may show an unknown-publisher warning.
