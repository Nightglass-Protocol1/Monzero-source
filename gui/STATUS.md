## Found by live-chain runs (fixed 2026-10-16)
The fixed-chain regtest harness never waits for real blocks, so it missed these:
1. **Peer connection dropped after 5 minutes idle.** XMZ confirmations take
   ~20 min, so every real trade lost its peer before redemption. Fixed: the
   negotiation session sends a keepalive every 60 s.
2. **XMZ checks failed whenever the wallet lagged the daemon** (wallet
   confirmations vs daemon tip) or a block landed mid-read. On mainnet this
   would hit ~15% of checks; in the trade session it aborted the trade, and a
   failed refund preparation could not be retried. Fixed in the engine: refresh
   the wallet first and re-read (max 4×) only on chain movement. Identity,
   amount and depth rules are unchanged. Patch `upstream-xmz-live-observation.patch`.
3. **Kill switch blocked regtest starts without a ledger file** (regression
   from the kill-switch change; broke the Qt trade fixtures). Fixed.

## Timing rules for choosing trade parameters
- A signed quote is valid ≤ 1 h and the XMZ lock must be sent before it expires.
- Redemption is released only while the LTC lock depth + 2 < `cancel_blocks`.
  XMZ needs 10 confirmations (~20 min) after the LTC lock confirms, so
  `cancel_blocks` must cover that in LTC blocks with margin. Mainnet (2.5 min
  blocks): use ≥ 36, not 20. Testnet LTC blocks are irregular: use ≥ 72.

## Known gaps
- Fixed 2026-10-17: a connection that drops mid-trade now comes back without a
  restart. `LitecoinPeerStartup` rebuilds the session from the saved trade (the
  verified restart path), retries at 2 s doubling to 60 s, and re-sends the
  already signed recovery agreement. Protocol failures are never retried.
  It also repeats settlement steps already under way (the funding proof, and a
  release the user approved for that same funding) and keeps a finished
  settlement finished. Regtest, link cut on either side (`--drop-connection
  alice|bob --drop-stage locks|proof|release`): all six cases passed (success at
  every stage, refund after the locks), reconnected in 33-54 s.
  Edge case left: if only one side finished settlement before the drop, the
  other may need the user to repeat the step (coins are settled on chain).
- Fixed 2026-10-17: the light wallet read no MWEB transactions (HogEx peg-outs,
  peg-ins), so a payment from an MWEB wallet broke its refresh. Verified on
  testnet with a real peg-out (`core/build/ltc-light-mweb-testnet-20261017.json`).
- Litecoin reads also abort on a tip change mid-read; with 2.5 min blocks and
  millisecond reads this is very rare and the user can retry the step.
